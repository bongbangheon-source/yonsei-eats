## 범위·위험·보존

- 테이블/컬럼/RLS/Auth 변경 없이 해당2행만 조건부 갱신한다. 나머지18곳·리뷰·즐겨찾기·기존seed/JSON을 변경하지 않는다.
- ID와 기존 식당명 검사, 현재 주소·좌표가 NULL 또는 동일 검증값인지 확인한다. 충돌이 있으면 전체transaction을 중단하며 기존값을 덮어쓰지 않는다.
- 잠금을 획득한 뒤 검사·수정한다. source_url이 이미 있으면 보존하고 pending상태만partial로 변경한다. 전반검증날짜 verified_at은 채우지 않는다. 미확인가격/시간/사진/현재영업상태는 그대로다.
- 재실행은 변경없으면 UPDATE를 건너뛰어 updated_at도 유지한다. 적용후2행 외 값이 변경됐다고 보고하지 않는다.
- 전체SQL의 begin/commit을 함께 실행한다. 초기 migration/seed를 다시 실행하거나 부분오류를 무시하지 않는다.
- 지도는 레지스트리와 DB값이 정확히 일치할 때만 마커를 생성한다. 사용자 승인 전에는 DB좌표NULL을 레지스트리값으로 조용히 대체하지 않는다.

## 검증/되돌리기 경계

격리PGlite검사에서2건/18NULL,기존값·리뷰·즐겨찾기·집계보존,충돌/이름불일치/누락ID의전체rollback,재실행불변을 확인한다. 원격적용후공개 SELECT로 재확인한다. 되돌리기가 필요하면 적용전값/기존source_url/status를 확인한 별도SQL을 검토하며 자동초기화하지 않는다.
