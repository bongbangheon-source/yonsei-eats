# Phase 6 배포 및 최종 제출 준비 계획

대상 GitHub: `bongbangheon-source/yonsei-eats`. 사용자 지시에 따라 기존 이력을 보존하고 commit/push/외부 연결/운영 설정은 승인 후 수행한다. Supabase 테이블·데이터·RLS와 기존 기능은 변경하지 않는다.

1. 로컬 상태/3개 기존 커밋/원격 refs/연결 계정 권한 확인. 실제 환경 값·비밀 패턴·이력·문서/바이너리 개인정보 검사. 현재 파일과 과거 이력의 검사 결과를 구분한다.
2. Vercel 공식 문서와 현재 코드의 환경 변수·Node24·Next 빌드 경로 확인. 임시 Node24로 호환성 검사하며 전역 런타임 변경은 하지 않는다.
3. npm test/lint/typecheck/build, 사용자 명시대로 db 3회 실행. 원격 쓰기 없이 기존 DB/위치 조회도 확인한다.
4. 제출용 문서/스크린샷, 배포 설정표/운영 테스트 매트릭스/안전한 업로드 파일 목록 작성. 추측 URL·미실행 테스트를 완료로 표시하지 않는다.
5. 안전한 파일만 stage, stage 내용을 다시 검사하고 파일 목록·커밋 메시지를 사용자에게 제시한다. 실제 commit/push는 별도 승인 후. 강제 push/이력 재작성/원격 덮어쓰기는 하지 않는다.
6. 승인된 Vercel 연결 후 GitHub import/Next.js/Node24/Production 공개 환경 변수/production branch를 검토한다. 실제 프로젝트 생성·배포·운영 설정은 구체 설정 승인 후 수행하거나 사용자가 Dashboard에서 직접 실행한다.
7. 실제 URL 확보 후 Supabase Site URL/Redirect URLs/메일 템플릿과 NAVER 허용 도메인을 승인된 범위로 설정한다. 공개키는 Dashboard에서 안전하게 입력하고 비밀키/토큰은 받거나 출력하지 않는다.
8. 실제 사이트 HTTP·브라우저 검사 및 사용자 실제 인증/쓰기 검사 결과를 구분해 기록한다. 제출 보고서에 최종 URL·커밋/배포 상태·화면·기능·DB/RLS·AI/프롬프트 개선·오류·미검증을 반영한다.

## 확인 및 승인 기록

- GitHub 연결 계정/대상 저장소 및 push 권한 확인. 원격은 초기 빈 저장소이며 로컬 origin은 아직 미설정이다.
- 기존 커밋 작성자 이메일과 과거 PDF/ZIP 로컬 경로 메타데이터를 사용자에게 설명했고, 사용자는 **이력 보존 및 공개 허용**을 회신했다. 값을 문서에 복사하지 않는다. 이는 실제 commit/push 승인과 별개다.
- Vercel 연결 안내 표시는 사용자가 승인했다. 연결 도구가 확인되기 전 설치/로그인 완료를 가정하지 않는다. 실제 배포 승인은 아직 받지 않았다.
